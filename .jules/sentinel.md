## 2024-05-24 - DoS Risk and Information Leakage via Unhandled Exceptions
**Vulnerability:** The application's `/predict` route casted form inputs directly to floats using `float(request.form['field'])` without exception handling. Supplying non-numeric, missing, or invalid data resulted in a `ValueError`, `KeyError`, or `TypeError` that wasn't caught, causing the Flask application to crash the specific request handling flow and return a 500 Internal Server Error. Concurrently, `app.run(debug=True)` was active, which exposed internal stack traces when such errors occurred.
**Learning:** This combination poses a Denial-of-Service (DoS) risk (triggering expensive 500 error handling repeatedly) and an information disclosure risk (leaking internal application architecture through stack traces). While debugging mode is useful for development, it should strictly never be deployed to production.
**Prevention:** Implement defensive programming for all direct typecasting from user input by wrapping it in `try...except` blocks and returning graceful 400 Bad Request responses. Additionally, explicitly enforce that `debug=False` (or entirely remove `debug=True`) in the production startup configuration.
