## 2024-03-09 - Unhandled Input Parsing Leading to Server Errors
**Vulnerability:** The `/predict` endpoint attempted to immediately access and cast `request.form` items to floats. If any expected key was missing, or if the user provided non-numeric string data, a `KeyError` or `ValueError` would be raised. This unhandled exception resulted in a 500 Internal Server Error.
**Learning:** Returning 500 errors on invalid user input is bad practice because it obfuscates the actual client error (Bad Request) and can potentially leak stack traces if debug mode is active. Furthermore, forcing the server to throw an exception repeatedly on bad input creates a denial of service (DoS) vector.
**Prevention:** Always wrap form data extraction and parsing in a `try...except` block that catches expected exceptions (like `KeyError`, `ValueError`, and `TypeError`). On exception, return a `400 Bad Request` explicitly with an appropriate minimal text message. Additionally, ensure `debug=False` is set when running the production server to disable stack trace exposure.
