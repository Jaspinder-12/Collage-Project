## 2024-05-18 - [CRITICAL] Disable Debug Mode and Add Input Validation
**Vulnerability:** The application was running Flask in debug mode (`app.run(debug=True)`) in production, which can expose sensitive stack traces and potentially allow Remote Code Execution (RCE) via the Werkzeug debugger. Additionally, the `/predict` endpoint lacked input validation, leading to unhandled `ValueError` and `KeyError` exceptions on invalid data (e.g. non-numeric characters) that cause 500 Internal Server Errors, creating a Denial of Service (DoS) risk. Finally, the application used hardcoded Windows paths (`r"D:\projects\BigMart-Sales-Prediction-With-Deployment-main\models\sc.sav"`) that leaked internal server structure.
**Learning:** Hardcoded model paths in machine learning applications are a common anti-pattern that leak internal file structures. Missing basic form validation is common when forms are directly mapped to `float()` without checking the presence or type of data first.
**Prevention:** Always set `debug=False` for Flask applications. Use a `try...except (KeyError, ValueError, TypeError)` block around user inputs, explicitly cast them, and fail securely with a 400 Bad Request JSON response if casting fails. Always use relative paths like `os.path.join(os.path.dirname(__file__), ...)` to load models or resources.
