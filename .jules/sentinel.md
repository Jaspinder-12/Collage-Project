## 2024-05-24 - DoS Risk and Information Leakage via Unhandled Form Parsing
**Vulnerability:** The `/predict` POST endpoint in `app.py` directly casted user-supplied form data to `float` (`float(request.form['...'])`) without a `try-except` block. Submitting missing or invalid (non-numeric) form fields caused unhandled `KeyError` or `ValueError` exceptions, resulting in HTTP 500 Internal Server Errors. In combination with `debug=True` being enabled in `app.run()`, this resulted in leaking stack traces and application internals to the user, acting as an Information Disclosure vulnerability and a potential DoS vector by crashing threads.
**Learning:** Directly parsing input from request data without error handling creates vulnerabilities. Unhandled exceptions in Flask will bubble up, and if debug mode is on, full stack traces are sent to the client. This codebase is vulnerable to missing input validation.
**Prevention:** Always wrap form and input parsing in `try-except` blocks (catching specific exceptions like `KeyError`, `ValueError`, `TypeError`). Return explicit user-friendly error messages with appropriate 4xx HTTP status codes (e.g., `400 Bad Request`). Never deploy Flask applications with `debug=True`.
