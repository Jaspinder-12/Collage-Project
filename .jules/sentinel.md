## 2024-05-24 - DoS risk and Stack Trace Leakage via Unhandled Input
**Vulnerability:** The `/predict` endpoint attempted to cast form inputs directly to floats using `float(request.form['field'])`. If a field was missing or couldn't be converted to a float, it raised an unhandled exception (KeyError, ValueError, or TypeError), causing a 500 Internal Server Error. When Flask's `debug=True` mode was active, this leaked the application's internal stack trace. Additionally, repeated invalid inputs could lead to Denial of Service (DoS) due to unhandled exceptions.
**Learning:** Raw input must always be validated and parsed safely. The assumption that the frontend will only send valid float data is dangerous. Additionally, debug mode must strictly be disabled in production to prevent sensitive information disclosure.
**Prevention:** Wrap input parsing in a `try...except (KeyError, ValueError, TypeError)` block to gracefully handle malformed data and return a secure 400 Bad Request error as plain text, avoiding JSON responses for HTML form submissions. Always ensure `app.run(debug=False)` in production environments.
