## 2024-03-08 - [Uncaught Exception DoS Risk in /predict and Info Leakage in Flask run]
**Vulnerability:** The `/predict` route directly casted user-supplied form data to `float()` without error handling. A user submitting missing or non-numeric data would trigger a 500 Internal Server Error. Additionally, the Flask app was run with `debug=True`, exposing stack traces and sensitive internal configuration upon error, leading to potential Information Leakage. This could also be used to trigger a Denial of Service (DoS) by sending numerous malformed requests.
**Learning:** External user input must always be validated or handled safely, specifically when casting or manipulating data structures. 500 Internal Server errors resulting from malformed input are an anti-pattern and security risk. `debug=True` should never be active in production setups.
**Prevention:** Always wrap data casting or extraction from untrusted sources (e.g., `request.form`) in a `try...except` block, safely handling `KeyError`, `ValueError`, and `TypeError`. Return a proper HTTP client error status code (e.g., 400 Bad Request) instead of failing to a 500 error. Always initialize application runners with `debug=False` for production deployments.
