## 2024-04-12 - Information Leakage via Debug Mode and Unhandled Exceptions
**Vulnerability:** The Flask application was running with `debug=True` in the main execution block. Furthermore, form input validation in the `/predict` route lacked error handling, meaning invalid or missing inputs triggered unhandled `ValueError` or `KeyError` exceptions. This configuration allowed detailed stack traces to leak to users whenever an error occurred, exposing internal implementation details and environment structures.
**Learning:** Development configurations (`debug=True`) are often left in codebase deployments by mistake. Additionally, casting raw request data directly (e.g., `float(request.form['key'])`) without exception handling creates highly fragile endpoints prone to exposing internal state upon encountering unexpected data.
**Prevention:** Always ensure `debug=False` for production deployments. Input parsing from external requests should always be wrapped in a `try...except` block to catch expected casting and dictionary lookup errors, returning a generic, safe error message (e.g., "Invalid input data" with a 400 status code) instead of throwing an unhandled 500 error.
